Senior DevOps Assessment: Greenfield Deployment

Welcome. We are launching a new Java Spring Boot microservice (a payment processor) that needs to be deployed to our production Kubernetes environments. Your task is to take the provided raw application code, containerize it, write the deployment configuration, build the automated pipeline, and ensure it correctly connects to our database.

Scope of Work (No Coding Required): Do not write or modify the provided Java application code. Assume the application logic, REST endpoints, and database connections are already completely functional. Your focus is strictly on the platform, the infrastructure, and the delivery pipeline. The application does not need to actually execute.

Tooling Constraint: While we respect experience in native cloud IaC tools (like Bicep or CloudFormation), our environments span multiple cloud providers. Therefore, Terraform is a hard requirement for the infrastructure portion of this submission.

Your Deliverables

1. Containerization

Write a production-ready Dockerfile for the provided Java application. Ensure it is optimized for size, security, and runtime efficiency.

2. Infrastructure as Code

Write a reusable Terraform module to provision the following infrastructure (you may assume AWS or Azure):

  • A managed Kubernetes cluster.
  • A PostgreSQL database instance.
  • Constraint: The database must reside in a strictly private network with zero public internet ingress. The cluster must be configured to communicate with it securely.

3. Kubernetes Manifests

Provide the YAML files (Deployment, Service, etc.) to deploy this container to the cluster. Ensure the deployment is highly available, resilient to node failures, and securely retrieves its database credentials.

4. Automation Pipeline

Provide a CI/CD pipeline definition (e.g., GitLab CI or GitHub Actions) that builds the image, pushes it to a registry, and updates the infrastructure and cluster. The pipeline must be optimized for execution speed and include necessary security gates.

5. The Reality Check

Assume our PostgreSQL database is deployed in the same cluster environment. However, due to legacy volume attachment limits, the database takes up to 60 seconds to fully initialize and accept connections after a cluster restart. The Java application crashes immediately if it cannot connect to the database on startup.

Solve this problem within your deployment strategy, and explain your solution in a short ARCHITECTURE.md file.

Please submit your response as a single tar.gz including all the files.
Do not actually provision the cloud resources.
